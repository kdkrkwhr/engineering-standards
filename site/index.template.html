어떤 프로젝트에서도
사람이 읽고 선택하는 기준

에이전트에게 맡길 작업의 범위와 검증 기준을 정하고, 사람이 코드의 구조·이름·흐름·판단 근거를 빠르게 찾기 위한 저장소입니다. 특정 언어, 프레임워크, 네 계층 구조를 모든 프로젝트에 강제하지 않습니다.

먼저 공통 원칙을 읽습니다

요구사항과 기존 계약을 우선하고, 책임과 의존 방향·오류·테스트·변경 범위를 확인합니다. 이름은 의미와 단위가 드러나야 하며 테스트는 구현을 그대로 베끼지 않고 독립된 기대 결과를 검증합니다.

공통 원칙 · 명명 규칙 · 구조 선택 가이드 · API·DTO · 트랜잭션

사용하는 언어의 표현만 선택합니다

공통 의미 규칙과 표기법은 구분합니다. Java, Python, Dart, C#, TypeScript의 이름·파일·패키지 또는 namespace 관례는 각각의 프로필에 있으며, 해당 언어만 선택합니다. 목록 밖의 언어는 같은 형식으로 추가할 수 있습니다.

Java · Python · Dart · C# · TypeScript

프레임워크 구조는 별도로 고릅니다

Spring Boot를 택한 프로젝트에는 presentation → application → domain → infrastructure 네 계층 프로필이 있습니다. 이는 사용자의 Spring 선호를 담은 선택지이며 다른 언어와 프레임워크의 기본 구조가 아닙니다.

Spring Boot 프로필 · 다른 프레임워크 프로필 템플릿

프로젝트 안에서 적용 범위를 기록합니다

이 표준 저장소가 다른 프로젝트에 자동 적용되지는 않습니다. 선택한 커밋·문서·예외·실행 명령을 소비 프로젝트의 프로필에 적고, 그 프로젝트의 루트 AGENTS.md와 기존 규칙을 합쳐야 합니다.

작업 범위와 입력·출력·수용 조건을 전달합니다. 결과에는 요구사항 → 파일·심볼 → 테스트의 연결, 짧은 코드 지도, 변경 이유, 실제 검증 명령·결과와 미검증 항목을 남깁니다.

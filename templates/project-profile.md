# 프로젝트 적용 프로필 템플릿

이 내용을 실제 프로젝트의 `docs/engineering-profile.md`에 **복사하여 채우고**, 프로젝트 루트 `AGENTS.md`에서 연결합니다. 복사된 표준 묶음의 `AGENTS.md`는 소비 프로젝트의 지침이 아닙니다.

## 적용 범위

- 프로젝트·기준 버전: `<프로젝트와 기준 커밋 또는 날짜>`
- 복사한 표준: `docs/engineering-standards/` / 원본 커밋 SHA `<고정한 커밋 SHA>` / 업데이트 방식 `<명시적 비교·병합 절차>`
- 이번 작업의 범위·입력·출력·수용 조건: `<프로젝트 요구사항 링크 또는 짧은 요약>`
- 채택 문서의 **프로젝트 내부 실제 경로**: `<docs/engineering-standards/standards/core.md 등 필요한 경로만>`
- 언어·프레임워크 선택과 제외: `<선택한 실제 경로와 제외한 프로필>`
- 확인한 프로젝트 명령: 빌드 `<실제 명령 또는 없음>` / 테스트 `<실제 명령>` / 통합 `<실제 명령 또는 미정>`
- API 계약(해당 시): `<URI/메서드/성공·오류 형식/페이지/재시도·멱등성/DTO 필드·알 수 없는 필드 정책>`
- DB 트랜잭션(해당 시): `<DB·버전·실제 기본 격리/쓰기 경계/락·제약·재시도/동시성 검증>`
- 기존 코드 관례와 충돌하는 부분: `<없음 또는 위치와 선택>`

## 코드 읽기 지도

`<요청·진입 파일>` → `<작업·정책 파일>` → `<저장·외부 파일>` → `<응답 파일>` → `<핵심 테스트>`

이름만 보고 역할을 찾을 수 있게 주요 패키지·모듈의 책임을 한 줄씩 적습니다. 작은 프로젝트면 두세 줄이면 충분합니다.

## 적용 규칙과 예외

| 규칙·강도 | 적용 범위와 이유 | 예외·종료 조건 |
| --- | --- | --- |
| `<MUST/SHOULD/MAY + 규칙>` | `<어디에 왜>` | `<기존 API/도구 제약 등>` |

플랫폼 안전·권한 제약을 지킵니다. 최신 명시 사용자 요구, 프로젝트 계약과 이 문서의 선택은 일반 기본값보다 우선합니다. 직접 충돌하면 임의로 요구를 바꾸지 말고 해결할 항목으로 드러냅니다. 예외 없이 적용되는 것처럼 쓰지 않습니다.
